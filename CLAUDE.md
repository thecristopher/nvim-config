# Eldentree, nvim-config

This is Cristopher's personal Neovim configuration. The my-style guide is always active for
every session in this repo (see the style section below).

---

## Project context

- Plugin manager: lazy.nvim (stable branch)
- All plugin configs live in `lua/plugins/` (one file per concern), returning lazy.nvim spec tables
- Core config (options, keymaps, autocmds) lives in `lua/core/`
- Franchise: `lua/core/franchise/` picks the world the whole config speaks, rotating one per day (Elden Ring, Resident Evil, Elizabeth). `:Franchise` or `<leader>jf` switches until midnight, `vim.g.eldentree_franchise` pins one. A lore with `opt_in = true` (Elizabeth's) only plays where `vim.g.eldentree_opt_in` names it, set in `lua/core/options_local.lua`, a git ignored file `core/options` loads and the `claude/*.lua` entry points read too. `names()` in `core/franchise/actions` is what this machine plays, `all_names()` every folder, for checkhealth and the specs. Each franchise is a lore folder in `lua/core/franchise/lore/<name>/`, discovered on its own (no list to register it in): `regions.lua` with the palettes, `skin.lua` with how components look, `lines.lua` with what the helpers and the HUD say, and `init.lua` with bosses, weather, banners, hub messages, message templates, landmarks, places, item categories and words. Modules read `require("core.franchise").current()` instead of keeping their own copies, so never hard code franchise text in a module. `mechanics` in each lore picks the version a module plays (`travel` fog, door or curtain, `boss` duel, stalker or scene, `status` grace, ecg or heartbeat, `rest` embers, typewriter or golden_hour, `ranking`), read it with `require("core.franchise").mechanic(name)`. `currency`, `merchant` and `banner_styles` (per kind overrides like the dripping death) live there too. What the HUD, the commit and PR helpers, `:Review` and `:Trial` say lives in each lore's `lines.lua`: every key and its plain line is in `lua/core/franchise/lines.lua`, a line may be a list (one is picked each time) and may use `{character}` (the region's character), `{traveler}`, `{world}` and its own holes. Read them with `require("core.franchise").line(key, vars)`, or `lines("hud", vars)` for every HUD word at once (views get them as `model.words` and read them through `parts.word`, falling back to the plain line), and never write a user facing word in those modules. Errors that explain a technical failure stay plain. `:checkhealth` asks every lore for every line. `:Franchise new <name>` copies `lua/core/franchise/template/` into a new lore folder, and `:checkhealth eldentree` runs `core/franchise/actions/validate.lua` over every franchise (missing words, bosses, weather, portraits, palette contrast, and a mechanic, view, picker or title style nobody built). Switching fires `User EldentreeFranchise`, everything that dresses up per franchise listens to it
- `lua/core/skin/`: applies the franchise skin: `vim.o.winborder` (so snacks pickers, hovers and Eldentree floats follow it), the cursor's shapes (`skin.cursor`, turned into `guicursor` by `core/themes/actions`), the small marks in `skin.glyphs` (indent guides and scope, listchars, fold and diff fill, the lines between windows (`split`) and the mark past the end of the buffer (`eob`), the picker prompt, which-key's icons, satellite's thumb and noice's spinner, registered as `eldentree`), pushed live into each loaded plugin by `core/skin/glyphs.lua` (every push in a pcall, they reach into plugin internals) while the specs read them on load, diagnostic signs, lualine separators and bufferline tabs (re-setup from their lazy specs on switch). Never hard code a float border or a level glyph, use `require("core.skin").border()` and `require("core.skin").icon(level)` (`skin.icons`, read by lualine, bufferline and every notification, snacks' own icons stay blank so the franchise's wins), and `require("core.skin").title(text)` for ornamented titles. Every glyph in a lore, skin or view must exist in the Nerd Font (JetBrainsMono Nerd Font Mono): symbols the font lacks get drawn by the terminal from another font with a different weight and size. Prefer the `md-` Material icons (the grace is `md-star_four_points`, the petals `md-flower`). The only exception is RE's `₧`, the merchant's currency, which has no icon. On `EldentreeFranchise` the skin re-setups lualine and bufferline after `forget_resolved_opts` drops lazy's cached opts, so the new franchise's separators and tabs really apply. BMP Private Use glyphs (U+E000 to U+F8FF) get lost when written as literal text: prefer `md-` glyphs and write a needed PUA glyph as a Lua escape (`"\u{E0BC}"`). `tests/core/glyphs_spec.lua` fails on any icon, glyph, sign or symbol key left `""` or `" "` outside its allow list
- `lua/core/hud/`: the start screen, an inventory HUD drawn in its own buffer (`eldentree_hud`), opened on an empty start, with `:Hud` or `<leader>jh`. `skin.dashboard` picks the view in `core/hud/views/`: `roundtable` (Elden Ring: category tabs, Inventory and Chest grids, the description under them), `inventory` (Resident Evil: STATUS panel with the survivor and DATA, plate tabs ITEM KEYS BOX FILE MAP EXIT, the COMMAND menu EQUIP CHECK COMBN, the item banner) and `wardrobe` (Elizabeth: a marquee sign, the tabs hanging as tags from a clothes rail, two framed columns, the rack with a close up of the selected piece and the stages with the call sheet of the quest, and her at center stage: her whole figure in a vanity mirror ringed with `◉` bulbs over a dressing table, `PORTRAIT_SHARE` of the rows its shape leaves and no taller than `PORTRAIT.max` (the same 36 as roundtable), with the rail over the rack on its left and the marquee sign over the stages on its right, the columns capped at `SIDE_MAX.center` and centered beside it. The mirror keeps center stage while its portrait stands at least `CENTER_SHARE` of the tallest any shape allows, otherwise it stands aside the whole body or above it, whichever is tallest). The hub chases light around every `◉` (`bulb_lit` in its actions), and a lore's `hud_tabs` renames the roundtable and wardrobe tabs (Elizabeth's Vanity, Props, Roles). Views are pure (model in, lines and marks out) and size themselves from the window in their `plan`: the portrait gets the room first and should always show: every shape is tried (beside a body of two columns or more, beside a single column, above the body with the name under it) and `biggest_portrait` in `core/hud/actions` keeps the one where it stands tallest, the quest or changed file rows give way before it does, then the grid, and in roundtable the quest's changes also give their rows up before the inventory drops under `GRID_ROWS.comfort` (two rows). In inventory both columns share their edges: the plates start on STATUS's top edge and DATA ends on its bottom edge, the room left over goes between the grid and DATA. The whole stage is centered, chunks carry a `spot` so the cursor and the portrait land exactly where the layout put them. The quest's last file is the newest recent file inside the project (`last_in`), not the newest anywhere. `core/hud/views/parts.lua` holds the pieces the views share (the champion's plaque, the quest block with branch and changes, the changed files). `core/hud/items.lua` fills the tabs from real data, and anything that needs a process (branches with their ahead counts in one `for-each-ref`, stashes, the map survey) goes through `core/hud/background.lua`, a cache fetched again in the background every 10 s that rebuilds the tabs when something new lands, so building them never waits on git. Snacks' image detection runs in the background too, and nothing may touch snacks' image code until the terminal answers: snacks would settle its environment without the answer (Ghostty is only known from it) and keep it all session. Meanwhile `supports_images` in `core/terminal` says no, `awaiting_images` says whether pixels are coming, and portraits asked for in that moment wait and draw on `User EldentreeImagesKnown` (hub keys in `core/hud/keys.lua`, recent files, branches and stashes, ground messages, regions, projects with changed file counts, map rooms), every item has `use`, `check` and maybe `combine`. hjkl move, Tab switches tabs, Enter uses (or opens COMMAND in RE), K checks, C combines, `?` opens the palette, the hub keys and digits still work directly. Reopening lands on the tab and slot you left (`resume_place`), unless the franchise changed. `core/hud/portrait.lua` draws the champion with chafa or real pixels, first throwing away snacks' converted copies older than the image (`stale_copies`), since snacks keys its cache by path alone and a recropped portrait would keep its old pixels, and converting and sending it again when its mtime changed during the session (`reload_if_changed`), since snacks also keeps every image it loaded in memory. The HUD's looks come from `hud_groups` in `core/hud/actions`, and its transitions start from a lit or sunk copy and fade to rest on core/motion's clock: the selection glows and settles on every move (`selection_flash`), a new tab flashes its plate or rule, and the whole HUD rises out of the background when it opens (`sunk`). The key hints color each key apart from its label (`hint_chunks`). The selected item's description types itself in (`typing_ms`, `reveal` in core/hud/actions, views cut it with `model.typed`). The trophies tab (`items.trophies`, counting in `core/hud/actions/trophies.lua`, words in `lore.trophies`) sits inside Resident Evil's FILE tab. While music plays, `parts.player` takes the stats row (the gap above the message in inventory), reading `core.music.now_playing()` and redrawing on `User EldentreeMusicChanged`. The snacks dashboard is off Each lore has a `hud.lua` (`lore.hud`): `keys` (name, slot, desc and flavor per hub key), `tabs`, `tab_icons`, `kinds` (category and flavor per item kind), `trophy_icons`, `stats` (the Roundtable's attributes, RE's conditions and ribbons, the call sheet's labels), `used` (the Roundtable's use toast) and Elizabeth's `guest_messages` (`GUEST_CHANCE`), and `validate` asks each view for what it reads. Roundtable: runes held in the corner, an item screen band (name, category, effect, italic flavor), a glint along the selected frame (`state.glint`, `glint_run`), the attributes under the plaque when every pair fits or in the footer otherwise, and an "Obtained" toast on use. Resident Evil: the grid is an attaché case (`pack`, `case_move`, `case_scroll`, `joint` in `core/hud/actions`, items carry `size`), with the condition (FINE, CAUTION, DANGER) under the survivor, the typewriter caret and ink ribbons on the banner, and Check opening a paged file reader (`pages`). Elizabeth: the call sheet reads SCENE, CAST, LOCATION and CALL, and a spotlight spills onto the rows beside the selection. HUD floats open beside the selection (`float_beside`) and hide the portrait while open, `:Hud` from a float opens in a regular window and wipes the blank start buffer, Recent files carry their folder when names collide (`file_labels`) and the trophies say where each number comes from. HUD text never shows a label or a sentence cut mid word: names are only cut where they break (`fit_words`, `fit_name`), dates, call times and DATA values shorten to their first whole form (`first_fit`), and greetings, flavor lines, messages and areas show whole or give their row away (`wrap_whole`, `parts.whole_line`)
- `lua/core/tree/`: the explorer dressed by the franchise. Guides and folders come from `skin.tree` (no expanders, the open or closed folder says it). A folder that is a room of `:Map` with errors or TODOs left carries `skin.tree.left`, cleared rooms stay bare, and folders carry no git status or diagnostics. Files carry their open review threads with a count (`core.threads.open_threads`, `User EldentreeThreads`) and their ground messages (`User EldentreeMessages`), and the file just saved glows (`EldenTreeFresh`). bufferline's offset is the explorer's one title (`chrome.tree` in the ornaments, `EldenTreeTitle`), and the root row names the project
- `lua/core/drift/`: the region's weather drifts through the empty rows under the last line of prose (markdown, text, gitcommit) and empty buffers, never in code, in one borderless float that takes no focus and lets clicks through, only in normal mode, sleeping with core/motion. `vim.g.eldentree_drift = false` turns it off
- `lua/core/title/`: the franchise title screen in block letters (shimmer, drip or a marquee of chasing bulbs), once a day per franchise and on every switch, `:Title`, `vim.g.eldentree_title = false`. The shimmer style writes the name in thin strokes (`THIN`) under the arc of the ring, and the drip style flickers like a failing light
- `lua/core/terminal/`: OSC 11 paints the terminal background with the region base, iTerm switches to the skin's profile when `vim.g.eldentree_iterm_profiles = true` (profiles in `terminal/iterm/Eldentree.json`), Kitty takes `kitty_opacity` with `vim.g.eldentree_kitty_remote = true`, Ghostty reloads `~/.config/ghostty/eldentree` written from the skin's `ghostty` table (macOS AppleScript, `vim.g.eldentree_ghostty_config = true`), only when the file changes. Each nvim leaves its pid in `eldentree_ghostty/` in state and only the last one to leave empties the file. After a reload `User EldentreeTerminalSettled` fires and the HUD portraits draw again, sending the image anew. A reload drops the images of every tab, so the nvim that reloads leaves its pid in `eldentree_ghostty_settled` in state and every other nvim dressing Ghostty polls it and fires the event too. `:Opacity [90|skin]` or `<leader>uo` overrides the skin's opacity in Kitty and Ghostty, saved in `eldentree_opacity` in state. The Ghostty file is written atomically (a temp file and a rename), a suspend only resets OSC 11, and quitting waits at most 500 ms for the reload
- `lua/core/sound/`: plays `sounds/<franchise>/<event>.{wav,mp3,aiff,m4a,ogg}` (variants as `event_2.wav`) for title, door, fog, curtain, rest, boss, merchant, phantom, continue (opening a repo visited before), summon, comfort, bought, welcome, weapon, expedition, the HUD's `hud_open`, `hud_close`, `hud_move`, `hud_select`, `hud_back` and every banner kind, `vim.g.eldentree_sound = false`, `:Sound <event>` previews. Some files are clips from the games, the rest are built by `scripts/sounds.py` (stdlib synthesis and ffmpeg), a recipe per event in its `RECIPES` table. A recipe may return a third value to finish it its own way (`FINISH`: the echo tail, the loudness, a gain and trimming the silence at the end): sounds that follow every keypress are built dry, short and quieter (`UI`), and every Elizabeth sound is trimmed so none rings past its moment (`FRANCHISE_FINISH`). All of hers are synthesized, timed to what they play under: the curtain to its 2.6 s animation, the title to the title screen, the rest lullaby long enough to nap to. The game clips are listed in `CLIPS` and finished by `--clips` (silence trimmed at both ends, a fade where one runs past its moment's `max`, evened out to the loudness the built sounds share, HUD clips left quieter), and `--import SOURCE FRANCHISE EVENT` brings a new clip in finished the same way. Every event a franchise plays has a file: Elden Ring builds its HUD, comfort and expedition sounds, Resident Evil its zone chime. Sounds travel on two channels: the HUD's (each one cuts the last, no buzz) and the moments' (`WEIGHT` in its actions: a heavier moment cuts a lighter one, a lighter one stays quiet). On macOS sounds play through a resident player (`core/sound/player.swift`, compiled by `swiftc` into `stdpath("cache")/eldentree/sound_player` whenever its source is newer, run by `core/sound/player.lua`): an `AVAudioEngine` that stays running with every file decoded once, since afplay took a second to wake the audio device on every sound and the HUD channel cut most of them before they were heard. afplay, paplay or ffplay are the fallback until it is built or where it cannot be. Nothing plays while nvim is unfocused except a `:Sound` preview, and a sound never repeats the variant it played last. `scripts/sounds.py` builds `VARIANTS` of the frequent sounds (`--variants`), and `CLIPS` may tame a clip's `peak`
- `lua/core/door/`: the dark and the door that opens when the franchise travels by door. `core/fog` hands any travel that is not fog to the module named after it (`core.door`, `core.curtain`), passing the project or branch you travel to. The door is sized to the screen, its planked panels slide into the frame, and `words.loading` sits small at the bottom
- `lua/core/curtain/`: velvet drapes in the region's accent close from both sides, announce the stage you travel to and part on it, for franchises whose `travel` is `curtain`
- `lua/core/heartbeat/`: the statusline heart for franchises whose `status` is `heartbeat`, beating with a lub and a dub, calm on a clean buffer and racing (broken at Danger) as the ECG's conditions get worse. It lives only in lualine, like the ECG
- `lua/core/ecg/`: the health ECG statusline piece (Fine, Caution, Danger) for franchises whose `status` is `ecg`. It lives only in lualine: the HUD and Claude's statusline leave it out, and the same goes for the grace glyph and the runes
- `lua/core/map/`: `:Map` / `<leader>jm`: each top folder is a wing and each room a box, red while errors or TODOs are left, blue when cleared, with the skin's `tree.left`/`cleared` glyph and the current room marked (▲), `<Tab>` steps between rooms and `<CR>` opens the files picker there. `layout` and `room_at` in its actions are pure, so a HUD tab can draw the same map. Room names are unique per project (`zones.zone_names`)
- `lua/core/results/`: counts saves and fixes per run, ranks it S to D on exit (`eldentree_results.json` in state), the HUD shows it in STATUS in the lore's `words` (`last_run`, `rank`, `saves`, `fixes`, required when `ranking` is on)
- Theme: catppuccin mocha recolored per region of the franchise in use. Color math lives in `lua/core/themes/actions/`, switch with `<leader>jr` or `:Region`. One region per day, the same in every repo and every launch (`of_the_day`, from the date and the franchise). Picking one with `<leader>jr`, `:Region` or the HUD holds until midnight (`eldentree_region` in state keeps the day and the name), and traveling between repos never changes it. `vim.g.eldentree_region` pins one everywhere. Each region has a `character` and a `portrait` in `images/portraits/` (pre-cropped to 828x1008, three times the 276:336 box the layouts use, game art with contrast and color lifted, the real photos in `PHOTOS` only lightly sharpened) that the hub shows when the file exists. Every portrait carries 72 DPI in its JFIF header (`stamp_density` in `scripts/portraits.py`, checked by `tests/core/portraits_spec.lua`): ffmpeg wrote its pixel aspect there and snacks, which sizes images by DPI, drew them a twentieth of their box. A region may also have a `figure`, the whole photo (662x1186, shaped 331:593 like `FIGURE_RATIO` in `core/hud/actions`), which views with `SHOWS_FIGURES` draw instead of the portrait (`image_for`), like the wardrobe's mirror. The originals live in `images/` and `scripts/portraits.py` crops them (`FACES` says where each face sits, `FIGURES` which ones also get a figure). Adding a region means a palette in the lore's `regions.lua`, plus its `weather` and `bosses` entries. Never hard code hex colors in plugin specs, read `require("core.themes").palette()` so they follow the region. Each skin has a syntax signature (`skin.syntax`: a color, a derived name or a palette slot, and a style per role, `italic = false` strips every italic). `core/themes/actions.syntax` resolves it so keyword, function and type stay apart from the error color and from each other. `derive` gives `keyword`, `func` (under the text), `comment` (contrast 3.2), `border` and `search`, so the accent marks focus (cursor number, mode, scope, titles) instead of every token. `validate.lua` checks the signature, the hue gap and the comment contrast. Traveling saves the old project's session (persistence) and restores the new one, unsaved buffers stay open. In Sites of Grace `<C-f>`, `<C-g>` and `<C-o>` travel and open files, grep or recent on arrival. Open Folder sends repos through the same travel, and `:BrowseFolders` walks folders in normal mode (`l` in, `h` up, `o` open, `.` open here). Switching branch with `<leader>gb` keeps a session per branch (`save_branch_session`, `restore_branch_session`)

- `lua/core/chrome/`: the editor's chrome per franchise. - `lua/core/leader/`: every leader key Eldentree binds, in `BINDINGS` of its actions (a `call` like `core.hud:open`, a `cmd`, a named `handler` or a snacks `toggle`), and every group with its which-key name and icon in `GROUPS`. - `lua/core/palette/`: `<leader><leader>` or `?` on the HUD, every Eldentree command with its key, in aligned columns and a window as wide as they need. `ENTRIES` in its actions is the list, add a row there when a module gets a command. A spec fails when a command defined in lua/core has no palette row and no reason in `UNLISTED`
- Floats and menus are opaque (`winblend` and `pumblend` 0, which-key and the toggleterm float too): any blend ghosted the code behind through their text. Only the effects that blend on purpose (fog, banners, the boss, rest, phantom, satellite's bar) set their own. Every float wears the same frame (`NormalFloat` and `FloatBorder` on `mantle`), the blink completion menu included, so it and its documentation read as one piece, and in the command line it shows only the label (`completion_columns`), since blink calls every command and path there a Property. `[d` / `]d` jump without a float, tiny-inline-diagnostic already writes the message beside the line, and the float `<leader>xd` opens names the source only when there are several (`source = "if_many"`)
- `lua/core/motion/`: shared animation engine (tween, ambient loop, highlight fades) on one clock: a single timer wakes for whoever is due next, beats count from the same epoch so rhythms that share a period land on the same frame, and it stops when nothing is due. `<leader>um` or `:Motion` stills everything, the plugins that animate on their own included (`vim.g.snacks_animate` for snacks scroll and indent, `vim.g.minianimate_disable`, smear's `enabled`), ambient loops stop while unfocused and a replaying macro jumps every tween to its last frame. Indent guides are snacks.indent, the region's rainbow in `EldenIndent1..6` and the scope in `EldenIndentScope` (catppuccin `custom_highlights`), drawn only on visible lines: indent-blankline recomputed its scope on every cursor move and was the biggest cost of moving around. `core.utils.refresh_statusline()` folds every call in the same tick into one repaint, so never call `lualine.refresh` directly. The code area stays calm: indent guides in one quiet tone with only the scope in the accent and no scope animation, rainbow only on brackets, treesitter context at most 2 lines following the topline on the panel color with a thin underline instead of a separator row, blame right aligned after 1.5 s, and `o`/`O` never continuing a comment
- `lua/core/spell/`: the repo's own spell word list in `spell/en.utf-8.add` (technical words, the franchises' names and the authors of the voice sheets), set as `spellfile` so `zg` adds to the same versioned file. The compiled `.spl` is git ignored and rebuilt on startup whenever the list is newer (`needs_build`). Add a word with `zg`, never by hand to a `.spl`
- Trouble groups diagnostics by file, its path from the project root, instead of under the absolute directory
- `lua/core/chrome/glint.lua`: every save of a real file sends a glint over the statusline (badge first, then branch, then the middle, mirrored on the right) on core/motion's clock, timing and colors in `chrome/actions/glint.lua`, always ending on the theme's exact colors
- `lua/core/chrome/yank.lua`: yanked text glows in the region's accent (`EldenYank`) and fades out on core/motion's clock, a short plain flash while motion is stilled, and every yanky put glows the same way (`prime_put` on `YankyPut`)
- Clipboard: `clipboard` is the system's, so only a yank or a `d` cut lands in it. `x`, `X`, `c` and `C` throw away what they remove, and `p` over a selection is yanky's put before, which keeps the register: pasting over two selections pastes the same thing twice

## Style: one source

The only style guide is `.claude/commands/my-style.md`. Everything reads it:

- a SessionStart hook in `.claude/settings.json` loads it into every new conversation
- `/my-style` runs it on demand in this repo (and `~/.claude/commands/my-style.md` is a symlink to it)
- `<leader>pc` and `<leader>pp` send it to Claude when drafting commits and PRs

Follow it with no exceptions. If it did not load, invoke `/my-style` before anything else.
Never copy its rules into other files, prompts or this one. Change the guide instead.

Developers using this config can swap that file for their own guide and every piece above follows it.
