# Eldentree, nvim-config

This is Cristopher's personal Neovim configuration. The my-style guide is always active for
every session in this repo (see the style section below).

---

## Project context

- Plugin manager: lazy.nvim (stable branch)
- All plugin configs live in `lua/plugins/` (one file per concern), returning lazy.nvim spec tables
- Core config (options, keymaps, autocmds) lives in `lua/core/`
- Franchise: `lua/core/franchise/` picks the world the whole config speaks, rotating one per day (Elden Ring, Resident Evil). `:Franchise` or `<leader>jf` switches until midnight, `vim.g.eldentree_franchise` pins one. Each franchise is a lore folder in `lua/core/franchise/lore/<name>/`, discovered on its own (no list to register it in): `regions.lua` with the palettes, `skin.lua` with how components look, and `init.lua` with bosses, weather, banners, hub messages, message templates, landmarks, places, item categories and words. Modules read `require("core.franchise").current()` instead of keeping their own copies, so never hard code franchise text in a module. `mechanics` in each lore picks the version a module plays (`travel` fog or door, `boss` duel or stalker, `status` grace or ecg, `rest` embers or typewriter, `ranking`), read it with `require("core.franchise").mechanic(name)`. `currency`, `merchant` and `banner_styles` (per kind overrides like the dripping death) live there too. `:Franchise new <name>` copies `lua/core/franchise/template/` into a new lore folder, and `:checkhealth eldentree` runs `core/franchise/actions/validate.lua` over every franchise (missing words, bosses, weather, portraits, palette contrast). Switching fires `User EldentreeFranchise`, everything that dresses up per franchise listens to it
- `lua/core/skin/`: applies the franchise skin: `vim.o.winborder` (so snacks pickers, hovers and Eldentree floats follow it), diagnostic signs, lualine separators and bufferline tabs (re-setup from their lazy specs on switch). Never hard code a float border, use `require("core.skin").border()`, and `require("core.skin").title(text)` for ornamented titles. Every glyph in a lore, skin or view must exist in the Nerd Font (JetBrainsMono Nerd Font Mono): symbols the font lacks get drawn by the terminal from another font with a different weight and size. Prefer the `md-` Material icons (the grace is `md-star_four_points`, the petals `md-flower`). The only exception is RE's `₧`, the merchant's currency, which has no icon
- `lua/core/hud/`: the start screen, an inventory HUD drawn in its own buffer (`eldentree_hud`), opened on an empty start, with `:Hud` or `<leader>jh`. `skin.dashboard` picks the view in `core/hud/views/`: `roundtable` (Elden Ring: category tabs, Inventory and Chest grids, the description under them) and `inventory` (Resident Evil: STATUS panel with the survivor and DATA, plate tabs ITEM KEYS BOX FILE MAP EXIT, the COMMAND menu EQUIP CHECK COMBN, the item banner). Views are pure (model in, lines and marks out) and size themselves from the window in their `plan`: the portrait gets the room first and should always show: every shape is tried (beside a body of two columns or more, beside a single column, above the body with the name under it) and `biggest_portrait` in `core/hud/actions` keeps the one where it stands tallest, the quest or changed file rows give way before it does, then the grid, and in roundtable the quest's changes also give their rows up before the inventory drops under `GRID_ROWS.comfort` (two rows). In inventory both columns share their edges: the plates start on STATUS's top edge and DATA ends on its bottom edge, the room left over goes between the grid and DATA. The whole stage is centered, chunks carry a `spot` so the cursor and the portrait land exactly where the layout put them. `core/hud/views/parts.lua` holds the pieces both share (the champion's plaque, the quest line with branch and changes, the changed files). `core/hud/items.lua` fills the tabs from real data, and anything that needs a process (branches with their ahead counts in one `for-each-ref`, stashes, the map survey) goes through `core/hud/background.lua`, a cache fetched again in the background every 10 s that rebuilds the tabs when something new lands, so building them never waits on git. Snacks' image detection runs in the background too, and nothing may touch snacks' image code until the terminal answers: snacks would settle its environment without the answer (Ghostty is only known from it) and keep it all session. Meanwhile `supports_images` in `core/terminal` says no, `awaiting_images` says whether pixels are coming, and portraits asked for in that moment wait and draw on `User EldentreeImagesKnown` (hub keys in `core/hud/keys.lua`, recent files, branches and stashes, ground messages, regions, projects with changed file counts, map rooms), every item has `use`, `check` and maybe `combine`. hjkl move, Tab switches tabs, Enter uses (or opens COMMAND in RE), K checks, C combines, `?` opens the palette, the hub keys and digits still work directly. Reopening lands on the tab and slot you left (`resume_place`), unless the franchise changed. `core/hud/portrait.lua` draws the champion with chafa or real pixels. The snacks dashboard is off
- `lua/core/title/`: the franchise title screen in block letters (shimmer or drip), once a day per franchise and on every switch, `:Title`, `vim.g.eldentree_title = false`
- `lua/core/terminal/`: OSC 11 paints the terminal background with the region base, iTerm switches to the skin's profile when `vim.g.eldentree_iterm_profiles = true` (profiles in `terminal/iterm/Eldentree.json`), Kitty takes `kitty_opacity` with `vim.g.eldentree_kitty_remote = true`, Ghostty reloads `~/.config/ghostty/eldentree` written from the skin's `ghostty` table (macOS AppleScript, `vim.g.eldentree_ghostty_config = true`), only when the file changes. Each nvim leaves its pid in `eldentree_ghostty/` in state and only the last one to leave empties the file. After a reload `User EldentreeTerminalSettled` fires and the HUD portraits draw again, sending the image anew. A reload drops the images of every tab, so the nvim that reloads leaves its pid in `eldentree_ghostty_settled` in state and every other nvim dressing Ghostty polls it and fires the event too. `:Opacity [90|skin]` or `<leader>uo` overrides the skin's opacity in Kitty and Ghostty, saved in `eldentree_opacity` in state
- `lua/core/sound/`: plays `sounds/<franchise>/<event>.{wav,mp3,aiff,m4a,ogg}` (variants as `event_2.wav`) for title, door, fog, rest, boss, merchant, phantom, continue (opening a repo visited before), summon, comfort, bought, welcome, weapon, expedition, the HUD's `hud_open`, `hud_close`, `hud_move`, `hud_select`, `hud_back` and every banner kind, `vim.g.eldentree_sound = false`, `:Sound <event>` previews. Some files are clips from the games, the rest are built by `scripts/sounds.py` (stdlib synthesis and ffmpeg), a recipe per event in its `RECIPES` table
- `lua/core/door/`: the dark and the door that opens when the franchise travels by door, `core/fog` hands off to it
- `lua/core/ecg/`: the health ECG statusline piece (Fine, Caution, Danger) for franchises whose `status` is `ecg`. It lives only in lualine: the HUD and Claude's statusline leave it out, and the same goes for the grace glyph and the runes
- `lua/core/map/`: `:Map` / `<leader>jm`, folders as rooms, red with errors or TODOs left, blue once cleared, `<CR>` opens the files picker there
- `lua/core/results/`: counts saves and fixes per run, ranks it S to D on exit (`eldentree_results.json` in state), the HUD shows it in STATUS
- Theme: catppuccin mocha recolored per region of the franchise in use. Color math lives in `lua/core/themes/actions/`, switch with `<leader>jr` or `:Region`. One region per day, the same in every repo and every launch (`of_the_day`, from the date and the franchise). Picking one with `<leader>jr`, `:Region` or the HUD holds until midnight (`eldentree_region` in state keeps the day and the name), and traveling between repos never changes it. `vim.g.eldentree_region` pins one everywhere. Each region has a `character` and a `portrait` in `images/portraits/` (pre-cropped, contrast lifted) that the hub shows when the file exists. Adding a region means a palette in the lore's `regions.lua`, plus its `weather` and `bosses` entries. Never hard code hex colors in plugin specs, read `require("core.themes").palette()` so they follow the region
- Leader: `<Space>` | Local leader: `\`
- `~/.config/nvim` is a symlink to this repo, so every saved `.lua` file is live immediately
- LSP uses native `vim.lsp.config` plus mason-lspconfig v2 (`automatic_enable`), servers live in `lua/plugins/lsp.lua`
- `lua/core/dive/`: F12 family (definition, Glance peek, references, F2 rename), bound on LspAttach. `K` hover floats are dressed as item descriptions (`item_categories` in the franchise lore)
- `lua/core/repos/`: background repo scanner, Sites of Grace picker (`<leader>fp`), auto root. A repo counts only when its `.git` leads to a readable `HEAD`. Traveling saves the old project's session (persistence) and restores the new one, unsaved buffers stay open. In Sites of Grace `<C-f>`, `<C-g>` and `<C-o>` travel and open files, grep or recent on arrival. Open Folder sends repos through the same travel, and `:BrowseFolders` walks folders in normal mode (`l` in, `h` up, `o` open, `.` open here). Switching branch with `<leader>gb` keeps a session per branch (`save_branch_session`, `restore_branch_session`)
- `lua/core/find/`: the pickers that need more than one Snacks call (recent files per repo with `<C-a>` to flip, branches with sessions). Every picker is Snacks, Telescope is gone, so never add one back
- `lua/core/chrome/`: the editor's chrome per franchise. The mode badge says the franchise's mode names (`chrome.modes` in the lore) and fades into the next mode's color, line numbers fade with their distance to the cursor (the statuscolumn wraps snacks' one), windows out of focus drop their cursor line and dim every number to the faintest step (`number_group(relnum, focused)`), so the eye finds the active window at once (trees, pickers and lists keep their cursor line, it is their selection), the statusline's language piece is the filetype icon plus the attached servers (`language_label`) and terminals are named by their shell (`terminal_title`), with no toggleterm extension so the bar stays the same everywhere, every statusline piece has a minimum editor width in `STATUSLINE_MIN` (music leaves first, the language last) so a narrow screen drops pieces instead of lualine cutting the bar with `<`, scratch screens like the HUD show neither a file name nor a language (`names_itself`), bufferline tabs are sized to their names (`tab_size = 12`) and a new file opens beside the current one, the neo-tree root shows the project's name instead of its path, there is no colorcolumn: `core/chrome/ruler.lua` tints only the part of a line past `textwidth` (or 100) with `EldenOverLength`, so inline blame and long comments are never split, and wrapped prose without a textwidth goes without (`ruler_applies`), closed folds carry their hidden line tally as a quiet italic note (`UfoFoldedEllipsis`) instead of catppuccin's bright pill, notifications are titled with the franchise's word for their level and the hour (`chrome.notify`), pickers take the layout the skin names (`picker`: `grace` or `inventory`) with titles between the ornaments and the preview called `chrome.examine`, and the noice command line is titled `chrome.cmdline` / `chrome.search` with the skin's `cmdline` glyphs, renamed in place on every switch. Words live in the lore's `chrome`, shapes in the skin, `:checkhealth` checks both
- `lua/core/leader/`: every leader key Eldentree binds, in `BINDINGS` of its actions (a `call` like `core.hud:open`, a `cmd`, a named `handler` or a snacks `toggle`), and every group with its which-key name and icon in `GROUPS`. Groups: `a` claude, `b` buffer, `c` code, `D` debug, `f` find, `g` git (`gh` hunks), `h` harpoon, `j` journey (the world's screens and the look of the day), `k` back to basics, `m` messages and threads, `M` multicursor, `p` pull requests, `s` windows, `S` sessions, `t` terminal, `T` tests, `u` toggles, `x` diagnostics. Never `vim.keymap.set` a global leader key inside a module, add a row there instead. Groups marked `owner = "plugins"` take their keys from lazy specs. Its specs fail on a key bound twice, a key that makes another wait for the timeout, or a palette key nobody binds
- `lua/core/palette/`: `<leader><leader>` or `?` on the HUD, every Eldentree command with its key, in aligned columns and a window as wide as they need. `ENTRIES` in its actions is the list, add a row there when a module gets a command
- Floats and menus are opaque (`winblend` and `pumblend` 0, which-key and the toggleterm float too): any blend ghosted the code behind through their text. Only the effects that blend on purpose (fog, banners, the boss, rest, phantom, satellite's bar) set their own
- `lua/core/motion/`: shared animation engine (tween, ambient loop, highlight fades) on one clock: a single timer wakes for whoever is due next, beats count from the same epoch so rhythms that share a period land on the same frame, and it stops when nothing is due. `<leader>um` or `:Motion` stills everything, the plugins that animate on their own included (`vim.g.snacks_animate` for snacks scroll and indent, `vim.g.minianimate_disable`, smear's `enabled`), ambient loops stop while unfocused and a replaying macro jumps every tween to its last frame. Indent guides are snacks.indent, the region's rainbow in `EldenIndent1..6` and the scope in `EldenIndentScope` (catppuccin `custom_highlights`), drawn only on visible lines: indent-blankline recomputed its scope on every cursor move and was the biggest cost of moving around. `core.utils.refresh_statusline()` folds every call in the same tick into one repaint, so never call `lualine.refresh` directly
- `lua/core/whitespace/`: trims trailing whitespace on save only on the lines that changed since the file was last written (a diff against the file on disk), so legacy files never drag untouched lines into a PR
- `lua/core/banner/`: Elden Ring style banners (`:Banner felled|great|died|grace|cleansed`) fired by commits, PRs, `:Trial`, new Sites of Grace, region changes and long fights with errors. `died` crumbles the window behind it into cellular-automaton rain (`lua/plugins/fun.lua`) and closes it as the banner fades, `vim.g.eldentree_rain = false` turns that off
- `lua/core/hub/`: the HUD's ambient life: shimmering gold on ornamented rows, a typed player message and per region weather drifting through rows without frames (`weather` in the franchise lore: embers, rot petals, glintstone, rain, snow)
- `lua/core/fog/`: fog wall that rolls over the editor when you travel to a Site of Grace (`:Fog`, `<leader>uf` or `vim.g.eldentree_fog = false`)
- `lua/core/messages/`: Elden Ring style messages left on lines of code, stored per repo in state (`<leader>mw` write, `md` erase, `ml` list, `:Inscribe`, `:Inscriptions`)
- `lua/core/folds/`: the closed fold text nvim-ufo shows (first line plus a hidden line tally)
- `lua/core/desk/`: the manager desk. `:Desk` / `<leader>jd` / `d` on the HUD opens the desk artifact, whose link and schedule live in a private config (`~/.claude/skills/desk/config.json`, or `vim.g.eldentree_desk_config`), so nothing company specific lands in this repo. Every `sync.every_minutes` inside work hours a cheap `claude --bg` session runs `/desk-sync check`, which reads the artifact's queue and leaves `check.json` in `eldentree_desk/` in state. Real work (analyses, replies) goes to a second session running `/desk-sync work` with a progress bar, implement requests open a tab with `claude "/ticket-implement KEY"` (`:DeskImplement KEY [repo]`), and review requests find the ticket's open PR with `gh search prs` in `github_org` and run `core/review` on it from the clone (`:DeskReview KEY`). Waiting is a file stat, never a Claude call. `:Desk sync` checks now, `:Desk status` tells when it last ran, `vim.g.eldentree_desk = false` turns it off and `vim.g.eldentree_desk_paused` skips the schedule
- `lua/core/review/`: `:Review [number|url]` / `<leader>pr` has Claude (headless, subscription) analyze a PR's diff into a float, `d` opens the diff per file
- `lua/core/git/`: quick git keys under `<leader>g` (`N` new branch, `j` pull, `k` push, `m`/`M` base branch, `z`/`Z` stash, `u` undo commit) and the related change staging `<leader>pc` runs first. `QUICK_KEYS` in its actions is the one list behind the keymaps and the toggleterm winbar hint. Keep `<leader>g` maps at two keys so none waits on a timeout
- `lua/core/btb/` and `lua/plugins/btb.lua`: back-to-basics (the clone in `~/Documents/GitHub/back-to-basics`, or `vim.g.eldentree_btb_dir`). The coach of the day is the `character` of the day's region (`coach_of` in `core/btb/actions`): Claire, Malenia and Ada (`PARTNERS`) by their own btb persona, anyone else handed to btb as `{ id, character, franchise }` so it summons them once, without romance, and the stage draws the region's portrait for them. `coach.training` and `coach.lessons` naming the hub key and the HUD tab. The stage draws the coach with `core/hud/portrait.lua` in its own `btb` slot, coach moments reuse the HUD sounds, and every `User BtbResult` fires `felled` on a clean solve or `great` on a level up and pays the XP in runes (a redo pays nothing). The plugin puts failing tests on the solution as warnings (on the line the stack or traceback reached), `<leader>kd` opens the solution beside the reference with Claude's review on the lines it names, a redo's winbar races its ghost, and `<leader>kk` asks the recapped lessons' closing questions before the recap. `before_hint` gets `M.before_hint` here, so the franchise's merchant sells each hint (`coach.hint`, `coach.buy`, `coach.leave`), greeting with `welcome` on the first visit of the day per franchise (`eldentree_merchant` in state) and `merchant` after that, while every pass plays `weapon` where the franchise has it and keeps the banner quiet and `User BtbHint` takes its XP out of the runes. `<leader>kC` / `:BtbConcepts` draws the concepts from `btb status` as rooms (`coach.concepts`). `b` on the HUD starts the lesson and its description reads what is left of the day (from `btb today`), the lessons fought so far live in the FILE tab (RE) or their own tab (Elden Ring). The pass that ends the day carries its summary in `BtbResult`, and the great banner closes it with a rank S to D. `<leader>km` / `:BtbPath` draws every track as a chain of levels. The plugin itself gives the solution a winbar (title, level, clock, hints, last test run, keys) and saving runs `btb test`, which never counts an attempt; dropbar stays off those buffers. `<leader>kk` lesson, `<leader>kb` library, the rest of `<leader>k` comes from the plugin
- `lua/core/progress/`: the one way to report a wait. `require("core.progress").start({ id, title, message })` keeps a notification on screen with a bar in the skin's `music.bar` style and the elapsed time, redrawn until `task:done(message)` or `task:fail(message)`, and `task:update(message, fraction)` changes the text or fills the bar. Anything slow (Claude, git over the network, gh, test runs, back-to-basics) uses it and runs async, so the bar never freezes and no status message expires halfway
- `lua/core/trial/`: `:Trial` / `<leader>TT` runs the project's tests in the background and announces the verdict
- `lua/core/boss/`: boss health bar for buffers where 3+ errors linger 8 seconds, the region's boss (`bosses` in the franchise lore) takes a hit per fix and the last one fires the `felled` banner (`:Boss`, `<leader>ub` or `vim.g.eldentree_boss = false`)
- `lua/core/boss/` also takes staged fights: `require("core.boss").stage(buf, { name, count, peak?, banner? })` lets another module count the hits instead of the diagnostics (`nil` ends it quietly, `banner = false` fells it without one). `core/conflicts` stages merge conflicts on it (`conflict` in the lore), and `core/btb` stages the onsite levels of back-to-basics from `User BtbFight`
- `lua/core/ci/`: the branch's CI run from `gh run list` in the statusline (`ci` in the lore), polled faster while it runs and never while unfocused, rechecked after `<leader>gk`. A run that finishes in front of you fires `felled` or `died`. `:CI` / `<leader>gi`, `vim.g.eldentree_ci = false`
- `lua/core/threads/`: the PR's open review threads through `gh api graphql`, as virtual text at the end of their lines, asked once per repo on the first file read (`vim.g.eldentree_threads = false` turns that off). `<leader>mc` / `:Threads` refetches and lists, `<leader>mo` opens the conversation, `<leader>mr` resolves after asking. Words in `threads` in the lore
- `lua/core/voice/`: the region's character speaks as a notification titled with their name when `:Trial` passes or fails, CI finishes, a push lands or an unstaged boss falls (`require("core.voice").say(moment, vars)`). Lines live per region and moment in the lore's `voices.lua` (`{branch}`, `{boss}` holes), written from the voice sheets in `docs/voices/`. `MOMENTS` in its actions is the list `:checkhealth` asks every region for, and `:Franchise new` copies `template/voices.lua` too. A region without lines stays quiet, `vim.g.eldentree_voice = false` silences all
- `lua/core/bestiary/`: diagnostics cleared by an edit (the changedtick moved, so closing a buffer fells nothing) count per code and repo in `eldentree_bestiary.json` in state, each code named from `bestiary.enemies` by `core.utils` hash. `:Bestiary` / `<leader>jb`
- `lua/core/expedition/`: `:Expedition [minutes|stop]` / `<leader>je` silences sound, motion and notifications below WARN, counts down in lualine and ranks the block with `core/results` math when it ends (`expedition` in the lore)
- `lua/core/chronicle/`: every finished run adds to its day in `eldentree_chronicle.json` in state, `:Chronicle` / `<leader>jc` draws the last 20 weeks lit by rank and by your commits in the repo (`chronicle` in the lore)
- `lua/core/phantom/`: `<leader>gw` / `:Phantom` blames the buffer through stdin and shows the last author as a phantom float
- `lua/core/zones/`: first visit to a folder each session fires the quiet `zone` banner, `landmarks` in the franchise lore names well known folders
- `lua/core/snapshot/`: `<leader>cp` / `:Snapshot` builds an SVG card from the on screen highlights and renders it with `rsvg-convert` to `~/Pictures/Eldentree`
- `lua/core/utils/`: project wide helpers (the stable `hash`, `refresh_statusline`). Write state files with `require("core.utils").write_state(path, lines)`, never a bare `writefile`: it skips the fsync that costs ~4 ms per write on macOS, and some state is written on every save
- `lua/core/links/`: opens links terminals print. Ctrl+click opens the one under the mouse in a toggleterm buffer (the terminal never sends Cmd to nvim) and hovering underlines it with `EldenLink`, `<leader>to` opens the last one printed in any terminal
- `lua/core/trace/`: `:InsertTrace` logs every exit from insert mode with the keys right before it (typed, mapped or sent by a plugin) to `eldentree_insert_trace.log` in state, off until toggled
- `lua/core/music/`: what Cider (REST API on `localhost:10767`, any OS) or Apple Music (osascript on macOS, the system media controls through Windows PowerShell on Windows, in `actions/windows.lua`) is playing, in the statusline. `<leader>o` or a click on it opens the now playing panel (`core/music/panel.lua`, layout in `actions/panel.lua`) with the album cover drawn by the HUD portrait, the song, artist and album beside it over a two row equalizer and the progress bar, and the lyrics from LRCLIB (`core/music/lyrics.lua`, timing in `actions/lyrics.lua`) between two dividers, the sung line swept karaoke style and its neighbors fading with distance, `l` shows or hides the lyrics (the panel shrinks without them), `j`/`k` scroll lyrics without timing. The bar, dividers and sung marks come from `music` in the skin, the panel title and lyric messages from `music` in the lore, `p` play/pause, `n` next, `b` previous. Covers are cached per album and lyrics per song in `stdpath("cache")/eldentree/music`, `vim.g.eldentree_lyrics = false` starts with the lyrics hidden, and hidden lyrics never ask LRCLIB. `:Music [playpause|next|previous]`. Cider is asked first, polling stops while nvim is unfocused. `vim.g.eldentree_cider_token` when Cider's auth is on, `vim.g.eldentree_music = false` turns it off
- `lua/core/claude_ui/` and `claude/`: Claude Code in the franchise. nvim rewrites `~/.claude/themes/eldentree.json` from the palette on `EldentreeRegionSettled` and `EldentreeFranchise`. `claude/*.lua` are tiny `nvim -l` entry points (they add the repo's `lua/` to the path, since `-l` skips the user config) for the statusline, the sound hook, the banner words and the installer, each calling `core.claude_ui.<name>.run`. `claude/install.lua` merges them into `~/.claude/settings.json`, replacing only its own hooks and keeping the first backup. Bar labels and spinner verbs live in each lore's `claude` table (`:checkhealth` requires it)
- `lua/core/claude_panel/`: the claudecode side panel (`DEFAULT_SHARE` of the editor). `<leader>aF` / `:ClaudeFullscreen` lets it take the whole editor (the rest folds to its border, `winwidth` drops to 1) and hides the HUD portrait, again to put the layout back with `core/resize`. While fullscreen, focus that lands on a collapsed window (a float closing, a picker looking for its main window) goes back to Claude so it never gets squeezed, and a new split ends fullscreen and resets the layout (`on_focus` in its actions)
- `lua/core/resize/`: resizing every window. Hovering a border lights it and draws a handle the mouse drags through, placed from the window's geometry so it rides the border while it moves. `<leader>sw` / `:Resize` lights the borders hjkl will move and moves them (shift for bigger steps, `=` resets), `<leader>se` / `:ResizeReset` puts the tree and the Claude panel at their defaults and equalizes the rest. The tree stays between `TREE_MIN` and `TREE_MAX` whatever moved it, except while Claude is fullscreen
- `lua/core/runes/`: statusline rune tally (saves and banners pay out, YOU DIED leaves a bloodstain) plus the breathing grace glyph
- `lua/core/rest/`: after 5 idle minutes in normal mode the editor rests at a Site of Grace (`:Rest`, `vim.g.eldentree_rest_after`), any key wakes it and is swallowed
- `lua/plugins/debug.lua`: nvim-dap with dap-view, F5/F9/F10/F11 plus `<leader>D`, js-debug and debugpy come from mason
- `lua/plugins/test.lua`: neotest (vitest, jest, pytest, plenary) under `<leader>T`, `:Trial` still owns the whole suite verdict
- Cursor colors follow the mode through `guicursor` and the `EldenCursor*` groups, smear-cursor follows them too
- `lua/core/lint/`: decides which nvim-lint linters can run (installed, and selene only with a `selene.toml`)
- Treesitter runs on the `main` branch (master crashes on 0.12), parsers build with the tree-sitter CLI
- `lua/core/vscode/`: when `vim.g.vscode` is set (Cursor/VS Code), only the allow listed editing plugins load
- `lua/core/style/`: reads the my-style guide so `<leader>pc` and `<leader>pp` draft with the same rules
- Pure logic goes in each module's `actions/init.lua` so it can be unit tested
- Tests: `./scripts/test.sh` (plenary busted, specs in `tests/`)

## Style: one source

The only style guide is `.claude/commands/my-style.md`. Everything reads it:

- a SessionStart hook in `.claude/settings.json` loads it into every new conversation
- `/my-style` runs it on demand in this repo (and `~/.claude/commands/my-style.md` is a symlink to it)
- `<leader>pc` and `<leader>pp` send it to Claude when drafting commits and PRs

Follow it with no exceptions. If it did not load, invoke `/my-style` before anything else.
Never copy its rules into other files, prompts or this one. Change the guide instead.

Developers using this config can swap that file for their own guide and every piece above follows it.
